# 整體網站 CSS 靜態調查

> 後續處理：使用者已同意整理，Beta目錄已移除，資訊頁現位於 `game-info/`；本文件下方是修改前的調查紀錄。實作結果見 `docs/ui-migration/SINGLE-SITE-CSS-CLEANUP.md`。

日期：2026-10-05。調閱範圍：正式／Beta 主網站、1204、光之聖所祈禱外層與 runtime、五個資訊表格、共通 CSS，以及 HTML／JavaScript 的載入和動態類別來源。

本輪未修改網站程式或樣式，未執行瀏覽器、圖片匯出或自動驗證。以下「未找到引用」限於目前儲存庫的來源調閱，不等同執行時覆蓋率證明。

## 結論

有舊 CSS 與可共用卻分開維護的內容。最值得優先處理的是正式／Beta 重複檔案、符文舊提醒規則、HEXA 懶人表的舊外觀覆蓋，以及共通表格基礎定義。

入口卡、標題卡、玻璃材質、檢視切換、寬度動畫、主要按鈕、欄位焦點、表格移入與底部版本資訊已有共通設計；不能因為頁面仍有自己的 CSS 檔就判定未套用共通樣式。

## 1. 正式與 Beta 重複維護

下列 17 組 CSS 檔案目前兩邊內容相同，但入口各自載入自己的檔案：

- `style.css`
- `assets/css/hexa-decisions.css`
- `assets/css/hexa-progress.css`
- `assets/css/home.css`
- `assets/css/hyper-stat.css`
- `assets/css/ignore.css`
- `assets/css/liberation.css`
- `assets/css/notice.css`
- `assets/css/rune.css`
- `assets/css/simulator-settings.css`
- `assets/css/standalone-tools.css`
- `1204/style.css`
- `light-sanctum-pray/style.css`
- `light-sanctum-pray/sound-toggle.css`
- `light-sanctum-pray/runtime/styles.css`
- `light-sanctum-pray/runtime/player-view.css`
- `light-sanctum-pray/runtime/pray-confirm-popup/styles.css`

這些檔案都有用途，不能直接刪除其中一份。建議先讓網站外層 CSS 採單一來源，再保留 Beta 專用覆蓋檔。頁面引用路徑、CSS 內相對素材路徑及部署範圍需要一起處理。

`assets/css/tool-shell.css` 與 `beta/assets/css/tool-shell.css` 已不同：正式檔具有 `site-note-compact-mobile` 的手機內距與換行規則，Beta 檔沒有。資訊頁載入根目錄版本，所以目前資訊頁會取得該規則；兩份繼續維護容易再產生差異。

祈禱 runtime 的三組 CSS 屬於遊戲畫面及彈窗。即使兩邊內容相同，也建議最後處理，保留其與網站玻璃元件的邊界。

## 4. 不應誤刪或硬套一致的內容

- `.hexa-current`、`.hexa-cumulative` 由 `hexa-${column}` 動態產生，仍控制單級／累積字重與數字位移。
- `.rune-tone-violet` 等符文配色由 `rune-tone-${symbol.tone}` 動態產生，仍有用途。
- `.bg-armor` 等無視防禦裝備分類由 `bg-${category.type}` 動態產生，仍有用途。
- 共通選取規則中的 `.is-target` 未找到目前實際使用者，但它只是複合狀態選擇器的一部分；不是獨立的整組廢棄樣式，不值得優先為此改動共通互動。
- 六轉進度的 `select:not(.site-select-control)` 是原生欄位備援／排除規則，不能只憑共通 select 已存在便整段刪除。
- 各工具的容器寬度、表格最小捲動寬度、列高、材料圖示裁切、手機欄位配置具有資料及功能用途，應保留。
- 模擬器遊戲內視窗、全螢幕、動畫與祈禱 runtime 並非一般網站資訊卡；不建議全部改成網站共通玻璃外觀。

## 建議處理順序

1. 統一網站外層正式／Beta CSS 的載入來源，處理已出現差異的 `tool-shell.css`。
2. 整理未引用的 `site-tinted-inset`、符文舊提醒及其動畫；保留 HTML／JS 資料來源關係。
3. 讓 HEXA 懶人表與資訊表格的基礎外觀由共通表格規則負責。
4. 抽出小型數值卡、圖示框與輔助閱讀文字的共通設計。
5. 最後整理舊 body 外觀與覆蓋規則，保留遊戲畫面的主題變數及專用樣式。
